# 2026-07-18 — Community catalog review fixes (2.8.0 "Failed")

The v2.8.0 release (commit b8793f8) failed the community-catalog automated checks. The
review page (community.obsidian.md/account/plugins/dataview-serializer) listed one
**Error** (blocking) and several **Warnings**. Fixed the blocking error and the
low-risk source/dependency warnings.

## Blocking error (caused the "Failed" status)

- **`@typescript-eslint/no-explicit-any` disable is not allowed** — the reviewer treats
  both the `any` and the `eslint-disable` as an error. Two sites:
  - `src/app/plugin.ts:36` (`getDataviewApi`) — replaced `(app as any).plugins…` with a
    local structural interface `AppWithPluginsRegistry` and `app as App & AppWithPluginsRegistry`.
  - `src/app/utils/serialize-query.fn.ts:107` — replaced `(vault as any).config` with a
    local `VaultWithConfig` interface describing just `newLinkFormat` / `useMarkdownLinks`.
    Removed the now-redundant `as string` / `as boolean` casts on the read values.

## Source-code warnings fixed

- **Unnecessary type assertion** — `src/app/plugin.ts:1434` (`isFileIgnoredByFrontmatter`):
  `FrontMatterCache` (`{ [k]: any }`) is already assignable to
  `Record<string, unknown> | undefined`, so dropped the `as Record<string, unknown> | undefined`.
- **`'unknown' overrides all other types in this union`** — `src/app/utils/device-disabled.ts:12`:
  `saveLocalStorage(key, data: unknown | null)` → `data: unknown` (`unknown` already
  subsumes `null`).

## Dependency warning (dev-only, partially addressed)

- Advisory card (GHSA-wv8q-r932-8hc7, `<3.49.0`) points to **svelte 3.35.0**, pulled
  transitively via `obsidian-dataview` (devDep, types only) → `obsidian-calendar-ui`.
  Added `overrides: { "svelte": "^3.59.2" }` in `package.json`; reinstalled → svelte 3.59.2.
- The card also lists other dev-only transitives (ajv, brace-expansion, fast-uri, flatted,
  handlebars, js-yaml, lodash, minimatch, picomatch, tmp) — most already at patched
  versions; all dev/tooling only, never bundled into `main.js` (runtime deps are just
  `date-fns` + `immer`). Left as accepted non-blocking warnings.

## Not addressed (non-blocking, deliberate)

- **`PluginSettingTab` does not implement `getSettingDefinitions()`** — new declarative
  settings-search API not present in obsidian typings 1.11.4. Implementing it would mean
  guessing an untyped shape and refactoring the whole settings tab. Left for a future
  pass once the API lands in the typings.
- **Build verification: build output ≠ released `main.js`** — persistent across all prior
  releases (which still show "Completed"), so non-blocking. Our build is deterministic
  (static banner, no timestamps/hashes); the mismatch is the reviewer using a different
  bundler toolchain than this repo's custom `scripts/build.ts`. Not resolvable from our side.

## Verification

- `bun run tsc`, `bun run lint` (--max-warnings 0), `bun test` (503 pass), `bun run build`
  all green. No UI behavior changed — pure type-level and dependency changes.

## Follow-up

- These fixes ship in the next release; the "Failed" status should clear once a new
  version (with the `any` disables gone) is published and re-reviewed.
