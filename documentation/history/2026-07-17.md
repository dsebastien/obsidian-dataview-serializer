# 2026-07-17 — Two-phase release workflow

Ported the fixed release workflow from obsidian-remarkable-sync (proven live with its 1.5.0 release). The old `release.yml` built and attested artifacts at the triggering commit, then created the version-bump commit and tag — so the build-provenance attestation was bound to a different commit than the release tag, and the community-catalog review rejected the release ("attestation failed cryptographic verification").

New design: a `prepare` job (dispatch on a branch) bumps versions, generates the changelog, builds + runs tests as a gate, commits, pushes a lightweight tag, then re-dispatches the workflow at the tag ref with `publish=true`; a `publish` job (dispatch-at-tag or bare tag push) builds, attests (`continue-on-error` removed), and creates the GitHub release — `github.sha` now equals the tag commit, so the Sigstore certificate matches.

- `.github/workflows/release.yml`: replaced verbatim with the reference file (old file was byte-identical to the shared old workflow; build paths `dist/*`, scripts `release:update-version`/`release:version-bump`/`release:changelog`, and the `git add` list including `docs/release-notes.md` all match this repo). `bun test` kept in the release gate (497 tests pass).
- `scripts/release.sh`: updated the "The GitHub workflow will:" description to match the two-phase flow.
